# Compatibility with Emacs Org

The parser follows the [Org Syntax spec](https://orgmode.org/worg/org-syntax.html); where the spec is ambiguous, Emacs `org-element` (Org 9.8.7) decides. `test-fixtures/org/parser/*.org` are compared with the element tree `org-element-parse-buffer` builds (`*.tree`, regenerated by `scripts/gen-fixtures.el`), so everything those fixtures cover is tested against Emacs. Nothing beyond them is claimed.

## Deliberate differences from org-element

| Input | Emacs 9.8.7 | This plugin | Why |
|---|---|---|---|
| `* Foo [#A] bar` | priority `A`, title `bar` | no priority, title `Foo [#A] bar` | The spec puts the priority right after the stars or the TODO Keyword. |
| A line holding only `*` (or `*` and a tab) inside a paragraph | starts a new paragraph | continues the paragraph | Not an element start in the spec; Emacs' list separator regexp matches it. |

## Not recognized yet (v0.1)

These parse as paragraphs or plain text, preserved verbatim: footnote definitions, LaTeX environments, dynamic blocks (`#+BEGIN:`), clock lines, Babel calls (`#+CALL:`), inline tasks, diary sexps, `COMMENT` Headings, description lists (`term :: text`) and item counters (`[@3]`).

Inline markup is single-line and not nested: an emphasis span is one token even if it holds a link. Plain links are recognized for `http`, `https`, `ftp`, `mailto`, `file` and `doi`.

Lowercase `[x]` is not a checkbox, as in the spec and Emacs; Toggle Checkbox still unchecks it (below).

## Structural editing

`test-fixtures/org/edit/OPERATION/NAME.org` with `NAME.expected.org` are golden tests for each operation.
`emacs --batch -l scripts/check-edit-fixtures.el` runs the matching Emacs command (`org-do-promote`,
`org-promote-subtree`, `org-move-subtree-up`, `org-todo`, `org-toggle-checkbox`, …) at each caret on Org 9.8.7 and
fails on any difference not listed here, or on a listed one that no longer differs.

| Operation | Emacs 9.8.7 | This plugin | Why |
|---|---|---|---|
| Any edit of a Heading with tags | re-aligns the tags to `org-tags-column` | leaves spacing as written | Preserve unrelated formatting. |
| TODO cycling on `*   TODO   x` | normalizes to one space around the keyword | changes only the keyword | Same. |
| Promote/Demote Heading with the caret in a Section | `M-←`/`M-→` move by word; promotion needs point on the Heading line (`org-metaleft`) | promotes or demotes the Heading the Section belongs to | The actions act on the Subtree around the caret. |
| `#+TYP_TODO` keywords | type semantics: a fresh Heading starts with a type keyword, repeated cycling jumps to done | cycle like `#+SEQ_TODO` | Type workflows are v0.2. |
| Toggling `[ ]` in a list whose siblings are all checked | also checks the parent item and updates `[n/m]` cookies | only the toggled checkbox changes | Statistics are v0.2. |
| Toggling lowercase `[x]` | becomes `[X]` | becomes `[ ]` | `[x]` reads as checked. |
| Several carets | — (Emacs has one point) | each Heading or checkbox changes once, one undo step | Several carets are an IDE feature. |

Visibility cycling has the same three states as Emacs, but reads the current state from the editor's folds instead of
the previous command, and drawers are not re-folded when a Subtree is shown (`docs/decisions/0004`). Blank lines that
end a Subtree stay visible when it is folded. Shift+TAB cycles the document only from a Heading line, so it still
unindents elsewhere.

## Editor highlighting

Typing the missing end line of an unterminated `#+BEGIN_SRC` block re-highlights its body only once the editor relexes from above the block; see `docs/decisions/0003`.
